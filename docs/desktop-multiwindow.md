# Desktop window and save boundary

The Electron host now creates independent renderer windows. File → New window (`CmdOrCtrl+Shift+N`) and `window.zorid.newWindow()` create an empty workspace in the caller's currently selected vault. The renderer must honor `getWindowInfo().initialState` before restoring a session. The first window has ID `main`, stable across launches; additional windows have UUIDs and `empty` initial state. Additional windows are not automatically restored on relaunch. The workspace integration owns per-window session/draft namespacing and legacy primary-window migration.

IPC identity comes from the registered BrowserWindow's actual WebContents and main frame, plus the exact application URL ignoring its hash. Renderer-supplied IDs never grant authority. Each window owns its vault selection. Every vault operation also supplies its expected canonical root; selection generation and live sender are rechecked after waiting in the operation queue. File dialogs and context menus use the calling window. Selecting a folder in one window leaves the other windows' bindings intact.

Canonical vault roots share one service and operation queue. `compareAndWrite(vault,path,expectedContent,contents)` reads and compares inside that queue and rejects a mismatch without writing. Ordinary writes, binary writes, renames, trash, directory creation and reads also pass through the same queue. The optional VaultAdapter method lets Vault.modify use this host operation while preserving the existing fallback for browser/mobile adapters and preserving post-write publication/error semantics. Atomic replacement remains the filesystem service's responsibility.

Changes, including explicit completed host mutations and external watcher events, go only to windows currently bound to the same vault. Events carry their vault root so detached renderer adapters can ignore delayed events. One watcher subscription is shared per active root and stopped when the last participant leaves; service/queue records remain until app shutdown so pending operations cannot split into separate queues. Operation errors do not poison the queue.

This serializes cooperating Zorid windows, not unrelated processes writing files concurrently between comparison and replacement. File creation and multi-file rename/link rewrite transactions retain their preexisting higher-level concurrency limitations. The host queue is not a cross-process filesystem lock. Moving a tab with its dirty buffer, editor history and view state requires the separately defined handoff/ACK integration; opening a path in a new renderer does not implement that operation.

Validation: broker tests cover authenticated window/frame/page identity, root-scoped broadcasts, watcher cleanup, stale queued operations, ordinary-write/CAS ordering, payload snapshots, and a real temporary-filesystem two-window race. Core tests cover CAS preference, conflict publication and uncertain write/readback failure. Actual Electron launch/keyboard verification remains a separate root-owned check.
