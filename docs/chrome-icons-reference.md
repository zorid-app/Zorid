# Desktop chrome and prebuilt icons

This pass addresses the supplied Zorid and Obsidian screenshot crops (`codex-clipboard-ButvqK.png` and `codex-clipboard-vunQ3A.png`). The observed defects were centered sidebar tabs drifting far from the window controls, a ribbon divider running through the macOS control area, missing header separation, approximate icon drawings, and mismatched file-toolbar glyphs/order. Different sidebar widths in crops do not establish a default width; this change preserves sidebar sizing and user resize behavior.

## Implementation

`dom.ts` retains its `icon(name, size = 18)` API and reexports the new Lucide-backed implementation. An optional third `ownerDocument` parameter permits Canvas and embedded documents to create their own SVG nodes without changing global document state. Existing aliases remain supported, unknown names still fall back to a file icon, and all SVGs are decorative while button labels remain accessible. Only named icon data imports are used; no dynamic complete icon registry is bundled. The module constructs fresh SVG nodes from that public icon data and preserves rectangles, circles, and paths.

Load `chrome.css` after `reference-defaults.css`. Its rules only affect desktop shell controls above the existing 700 px mobile breakpoint. The sidebar tab strip remains 40 px high, aligns left, and reserves macOS controls only when the workspace has `is-macos-desktop`. The first Mac tab starts at window x=88 px, independent of sidebar width. Header dividers continue across the ribbon/sidebar while the vertical ribbon divider begins below the control strip. File-toolbar padding and gaps match the bounded measurements. Sidebar-hidden top tabs receive the same macOS clearance. Toolbar glyph/action wiring and the desktop marker are integrated in `workspace.ts`/`main.ts` by the integration lead; no editor content styling is changed here.

## Verification and boundaries

Four focused tests verify API aliases, SVG shape preservation, independent-document ownership, independent node creation, fallback names, accessibility, existing button click behavior, and the actual CSS selector's restriction to the top-left leaf through nested split groups. TypeScript and production build pass. The production source map contains exactly 40 selected Lucide modules rather than the full icon set; existing CodeMirror/PDF bundle-size warnings remain.

An isolated headless Chromium fixture used the real shell styles and icon helper. At sidebar widths 200 and 340 px, it measured tab x=88, header height=40, toolbar y=40/height=40, ribbon-divider top=40, and icon width=16. Removing the macOS marker placed the first tab at x=52. The resulting screenshot was inspected. This verifies actual browser geometry for the bounded fixture, not native traffic-light hit testing or the integrated application. Native Electron screenshots at the user's zoom/window state, fullscreen behavior, sidebar toggle interactions, and mobile touch appearance still require integrated verification. The reference screenshot's home/ribbon actions may depend on user customization; toolbar order and functionality must stay consistent with the actual host commands rather than inserting nonfunctional decorative buttons.

Workspace wiring loads the chrome override after the default theme, sets `is-macos-desktop` only for the desktop bridge on Mac, and uses the audited five file-toolbar glyphs. Auto-reveal starts off and persists in the current workspace session; its toggle expands the active file's ancestors. Collapse/expand changes the tree and its glyph/label together. Static renderer anchors for these original behaviors: A1505947 (initial false), A1506500–1507400 (toolbar order), A1508329 (saved state), A1516518–1516780 (toggle), A1522399–1522700 (active-file reveal). This does not establish exact native folder animation or complete explorer parity.
