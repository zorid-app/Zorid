# Editor performance and lifecycle audit

Snapshot: 2026-10-16. This is a static audit of the original Zorid implementation, with proposed regression fixtures. No implementation was changed, no wall-clock benchmarks were run on the shared worker host, and no reference application or recovered code was executed. Costs below follow explicit loops, allocations and call sites; they are not measured latency or proof of a leak in a running browser. Parallel implementation work may move the cited lines; function names identify the corresponding code.

Reference comparisons reuse [editor-reference.md](editor-reference.md), [interaction-parity.md](interaction-parity.md), and the scope limits in [source-audit.md](source-audit.md). The retained desktop renderer identity is SHA-256 `958ce57fe22f87fdf121546e46dfccd9c8ee971ce3fd8f801d60d4ece39a2df9`, E3 `ev_a023c82af045a4b5acedab1eab958db521c3828491a6320c1f7ee85152573b37`. This report adds no proprietary source reading or new REA finding. Reference mechanisms are architectural evidence, not a measured performance target.

## Highest-value findings

### 1. Whole-note work occurs before the save debounce

[Editor update listener, `src/ui/editor.ts:164`](../src/ui/editor.ts#L164) materializes the full document for every local document update. [Workspace `onChange`, `src/ui/workspace.ts:290`](../src/ui/workspace.ts#L290) sends that string to `NoteBuffer.update`, synchronizes sibling editors, invalidates embeds, and updates status. At the original audit snapshot, NoteBuffer synchronously JSON-serialized **both saved base and current text** into storage on every update; the 400 ms timer delayed disk saving, not recovery serialization. The bounded persistence follow-up below changes that repeated work while retaining synchronous distinct-edit checkpoints. Workspace supplies `localStorage`.

Status rendering scans the full note for words and allocates `[...text]` to count Unicode code points ([`workspace.ts:373`](../src/ui/workspace.ts#L373)). It runs through the buffer's `onState` callback and again directly in `onChange`. Thus even a one-character edit to a plain note has document-sized application work independent of CodeMirror's incremental document representation. Each sibling editor's `setValue` also materializes its old document and scans common prefix/suffix ([`editor.ts:181`](../src/ui/editor.ts#L181)).

**Priority P1:** remove redundant status refreshes and maintain counts from changes, with exact Unicode/whitespace semantics. Preserve document snapshots at actual consumers instead of serializing independently in every layer. Consider a revisioned incremental recovery journal or explicitly durable checkpoint design before changing recovery persistence. Merely debouncing `persist` weakens the current recovery window and is not an equivalent optimization. Keep expected-content conflict checks and save failure retention.

**Fixture:** fixed 10 KiB/1 MiB/10 MiB notes, 100 one-character transactions at start/middle/end, one then two panes. Count string materializations, status refreshes, recovery writes and serialized bytes; assert one authoritative save result, preserved drafts after injected storage/write failures, and identical code-point/word counts for emoji, combining marks and whitespace. Collect native input latency only later on an idle host.

### 2. Block discovery traverses the parsed document on each edit

[`findEmbeds`, `src/editor/live-embeds.ts:30`](../src/editor/live-embeds.ts#L30) walks the entire available syntax tree, copies its parsed source prefix, regex-scans wiki embeds, sorts candidates and exclusions, and reconciles them. The field repeats this for every document change or syntax-tree identity change (line 150), then recreates the decoration descriptions. For parsed source length N, syntax nodes T, embeds E and excluded spans B, this includes O(N + T + E log E + B log B) work per rebuild, before render costs. Compatible DOM is reused through mapped identity and `WidgetType.eq`; discovery is still global. This does **not** mean every offscreen widget is mounted: CodeMirror controls DOM materialization.

[`liveTables.build`, `src/editor/live-tables.ts:259`](../src/editor/live-tables.ts#L259) likewise walks the full tree. Its cache avoids reparsing unchanged table text, which is valuable, but an insertion before a table calls `shiftModel` (line 251), copying every row and cell to shift absolute positions. The cache loop tests every changed range for every table (line 279), adding O(tables × changed ranges). Editing one cell reparses its table source and reconciles every cell in `TableController.update` (line 72).

**Priority P1:** map unchanged ranges first; invalidate discovery for parser-changed regions plus syntax context, not just the literal edit interval. Fence delimiters, table separators, frontmatter and reference definitions can change meaning beyond that interval. Store table-relative cell offsets with a table base to avoid copying all cells for a pure shift. Keep stable identities and source-range ownership through insertion, deletion, split and merge. Viewport-limited discovery must preserve block layout/height and reveal semantics; dropping offscreen block decorations without a layout model is unsafe.

**Fixture:** 10/100/1,000 tables or embeds separated by paragraphs. Edit an unrelated prefix and compare parse calls, scanned bytes, copied cells, widget mounts/destroys and active child identity. Edit fences/table separators before offscreen objects, scroll into them, then undo. Assert no embed appears in code, no cell changes ownership, and unaffected widgets retain their DOM. Add multi-range edits to expose the tables × changes path.

### 3. Ragged table models can amplify small source into large state

[`parseTable`, `src/editor/table-model.ts:105`](../src/editor/table-model.ts#L105) chooses the maximum row/separator width and materializes virtual cells for every shorter row. Each virtual cell stores a progressively longer repeated insertion prefix (lines 117–121). With R sparse rows and C columns, the cell count is O(RC), and the sum of generated prefix string lengths can be O(RC²), even though the sparse source itself is much smaller. Actual heap representation depends on the JavaScript engine; the logical string volume is visible statically. [`TableController.render`, `live-tables.ts:48`](../src/editor/live-tables.ts#L48) also creates a DOM cell for every modeled cell when that table mounts. There is no row virtualization inside the table widget.

**Priority P1:** represent virtual-cell insertion as a compact count/style and materialize only the chosen edit's prefix. Preserve the existing exact pipe, padding, line-ending and missing-cell insertion behavior. Row virtualization is a larger follow-up requiring explicit selection, measured heights and keyboard/clipboard contracts; do not hide data or silently cap columns to gain speed.

**Fixture:** one C-column header/separator and R two-cell rows, varying C = 16/64/256 and R = 16/128/512. Count model cells and sum insertion-prefix lengths without allocating an extreme fixture in the UI. Select/edit the final virtual cell, undo, reopen and verify exact source plus cursor position. Compare against equally sized rectangular tables to isolate amplification.

### 4. Interaction deferral is local to inline preview

[`createEditor` preview plugin, `editor.ts:103`](../src/ui/editor.ts#L103) captures mouse-down before hit testing, maps decorations while pointer selection or composition is active, and clears listeners/timers on destruction. This follows part of the retained stability contract. However, `liveEmbeds` and `liveTables` StateFields rebuild on document/tree changes without that interaction state. [`liveTasks`, `live-tasks.ts:85`](../src/editor/live-tasks.ts#L85) also rebuilds on selection/focus/doc changes without a composition/drag gate. No explicit “parser has reached the viewport” guard is present in these paths. Inline preview listens to tree changes but still builds from whichever partial tree exists.

Inline `decorations` scans visible **lines**, including their entire text ([`editor.ts:54`](../src/ui/editor.ts#L54)); a very long wrapped line may exceed the visible character extent. Each line checks every selection, and each emphasis candidate traverses syntax again with `inside` (line 48). Reveal is whole-line and does not test `hasFocus`; the update predicate omits focus changes. These are correctness/reveal gaps alongside optimization opportunities, not evidence that the retained reference's grouped-token and focus-sensitive rules are implemented.

**Priority P1 correctness prerequisite:** introduce shared interaction/parse-readiness state and defer geometry-changing rebuilds while mapping existing positions. Resume on current tree/selection after completion or cancellation; preserve nested table transactions that must still update source. Avoid blanket suppression of edits or parsing. Consolidate visible syntax traversal only after token/reveal behavior is specified.

**Fixture:** real browser mouse drag and IME composition/cancellation around inline markers, task markers, table boundaries and embedded images; insert a fence delimiter during composition; change selection before delayed refresh; destroy the editor before release. Assert source and selection endpoints, DOM identity during interaction, one final reveal refresh, and no post-destroy dispatch. Test a megabyte single line separately from many short lines. jsdom event dispatch cannot certify IME or measured caret geometry.

### 5. Embed caches bound concurrent I/O, not retained state or refresh work

[`MarkdownEmbeds`, `src/ui/embeds.ts:48`](../src/ui/embeds.ts#L48) uses IntersectionObserver for first visibility, coalesces reads by path and caps Markdown reads at four. After first intersection, a node is unobserved and `visible` stays true. Previously visited reading-view embeds therefore remain eligible for refresh even after scrolling far away. `invalidate` scans all states; each matching state destroys children and rebuilds its contents. Duplicate reads share a promise, but duplicate subpath selection/rendering do not: `refresh` calls `selectMarkdownSubpath` and `renderMarkdown` separately for every occurrence (lines 171–184). Fragment selection scans the source's lines/blocks in [`src/core/subpath.ts:75`](../src/core/subpath.ts#L75).

`reads` retains successful and failed promises until path/global invalidation or manager destruction. `releaseEmbed` releases resources and node state but does not evict the path's cached text. Pending jobs retain their path and continue after individual widget removal; only whole-manager destruction prevents queued storage access. Repeated invalidation while a slow path is queued can enqueue obsolete versions. Version checks correctly prevent those results from mounting, but do not cancel the read work. Concurrency four is not a queue-length or memory bound. Nesting depth five prevents infinite depth, not wide branching fanout.

**Priority P1/P2:** coalesce invalidations per revision/path; track unresolved dependencies and current visibility separately from “ever seen”; reference-count/cap detached text cache entries, with a retry policy for rejected promises. Cache immutable subpath parse results by source revision, not DOM nodes shared between parents. Cancel/deduplicate obsolete queued jobs while settling their promises. Preserve generation checks, cycle/depth protection, unsaved-buffer reads, source-relative link resolution and refresh after formerly missing targets appear.

**Fixture:** 100 duplicates of one heading embed, then 100 distinct sources; hold reads behind controllable promises, invalidate the same path 100 times, release widgets, then release I/O. Count reads, pending jobs, fragment parses, stale DOM writes, observers, child states and retained cache entries. Scroll past all embeds then modify an offscreen source. Add a branching embed tree and rapid source edits with equal-length content. Verify current output and complete cleanup, not merely an upper bound of four active reads.

| List continuation, [`list-commands.ts:57`](../src/editor/list-commands.ts#L57) | The math fallback scans from line 1 to each cursor on Enter; continuation lookup can also scan backward. | Frontmatter, [`live-properties.ts:12`](../src/editor/live-properties.ts#L12) | Valid hidden prefixes reuse their region on ordinary body edits. No-prefix notes return quickly, but a note beginning `---` with no closing delimiter rescans all lines on each change because `start === 0`. Cache the negative/unclosed parse state with correct invalidation when a delimiter is inserted; do not hide invalid YAML. |
| Completion, [`editor.ts:99`](../src/ui/editor.ts#L99) | Every completion invocation builds all Markdown-path labels; workspace first copies all entry keys. | Link resolution/backlinks, [`metadata.ts:104`](../src/core/metadata.ts#L104) | Direct path resolution uses sets; unresolved short wiki targets scan all files then sort candidates with repeated folder-distance calculation. | Attachments, [`attachments.ts:38`](../src/ui/attachments.ts#L38) | Reads are capped at four and active URL leases survive invalidation; final release revokes URLs. | Workspace retention, [`workspace.ts:224`](../src/ui/workspace.ts#L224), [`workspace.ts:394`](../src/ui/workspace.ts#L394) | Closing a tab flushes its buffer but leaves it in the workspace map. An LRU for clean unreferenced buffers must keep dirty/error drafts and active panes. | Core storage, [`vault.ts:57`](../src/core/vault.ts#L57), [`vault.ts:242`](../src/core/vault.ts#L242) | Initialization retains all Markdown contents and metadata; refresh temporarily retains old/new snapshots for atomic publication. Known-file saves index only the changed note; exact watcher batches read affected Markdown regardless of stats. Preserve these guarantees. Full structural refreshes and rename link rewrites remain vault-sized; they are separate from keystroke discovery. |
| Transfers, [`transfers.ts:75`](../src/editor/transfers.ts#L75) | Imports serialize and guard disposal before insertion; pending native reads are not aborted by destruction. Multiple files insert as separate transactions, invoking all note-update work repeatedly. Batching requires a defined async insertion anchor, nested-editor focus policy and undo grouping, rather than blindly combining writes. |

Positive lifecycle evidence: inline preview removes its document/window handlers and cancels timers (`editor.ts:147`); embed widgets disconnect ResizeObserver and destroy each owned renderer (`live-embeds.ts:129`); table controllers destroy their child editor and delete WeakMap ownership, while queued selection work has a version guard (`live-tables.ts:222`, `:285`); Markdown embeds guard asynchronous results by generation, unsubscribe vault events and release leases (`embeds.ts:117`, `:189`); attachment release is idempotent at the lease boundary and manager teardown prevents late object URLs (`attachments.ts:65`, `:83`). These paths deserve regression protection. Their presence does not establish absence of all leaks.

## Verification plan and current limits

Existing suites provide useful starting points: [editor-runtime tests](../tests/editor-runtime.test.ts) cover DOM reuse, parent undo, external snapshots and mouse-selection deferral; [live-embed tests](../tests/live-embeds.test.ts) cover source ownership, observer/renderer teardown and split/merge cases; [embed tests](../tests/embeds.test.ts) cover duplicate reads, concurrency and late completion; [attachment tests](../tests/attachments.test.ts) cover URL lease cleanup; [buffer tests](../tests/note-buffer.test.ts) cover concurrent saves, recovery and conflicts; [core performance tests](../tests/core-performance.test.ts) assert operation counts and atomic failure behavior. This audit read these fixtures but did not rerun them or claim new test results.

Add deterministic counters at discovery, parse, DOM mount/destroy, source-read, queue and recovery boundaries before introducing timing thresholds. Increase fixture size while holding edit size and viewport constant; report operation/byte growth, not a guessed Big-O label alone. Repeated open/edit/close cycles should return observer, listener, child-editor and object-URL counts to baseline, while separately reporting intentionally retained vault/buffer/cache state. Inject failures and out-of-order promise completion. No unbounded “wait until idle” should hide a never-settling queue.

At this snapshot, `createEditor` only installs live embeds when supplied `renderEmbed`, and the inspected workspace editor call did not supply it; list/task extensions existed separately from that editor extension stack. Exercise the real workspace integration before treating isolated extension performance as application performance. Recheck this wiring after parallel implementation changes.

After deterministic correctness checks pass, run controlled Zorid browser/native measurements on an idle host with fixed fixture bytes and parser readiness, recorded build/dependency versions, hardware, scale/fonts, viewport, warm/cold state and repetitions. Separate load, parse, input-to-paint, save, embed-read, allocation/GC and retained-memory measurements. Use median and tail latency and real IME/pointer tests. Reference comparison remains a separate authorized activity under [the interaction protocol](interaction-parity.md); neither this static audit nor passing Zorid tests certifies full Obsidian 1.14.4 parity.

## Bounded persistence follow-up

The isolated `parity/editor-persistence` implementation keeps the public `NoteBuffer` API and existing `{base, content}` recovery format. [`persist`](../src/ui/note-buffer.ts#L63) now remembers the last successful checkpoint by storage key, base and content, skips identical successful writes/removals, and caches JSON encoding of the saved base. Failed writes are never marked successful. `save` retries pending recovery before disk I/O, including explicit flush/dispose paths; duplicate updates do not reset an already scheduled autosave. Path migration and a changed saved base require a new checkpoint even if current text is unchanged. The extra serialized-base cache is released after successful clean removal. Cache ownership is per buffer; this adds no cross-window synchronization protocol.

No recovery debounce was introduced: every distinct dirty edit still attempts synchronous recovery before `update` returns. A visibility/pagehide hook cannot make delayed recovery equivalent to this contract because abrupt process loss need not deliver a lifecycle event. No workspace hook is required by this change. Any future scheduled mode needs an explicit acknowledged loss window or a synchronously durable incremental journal, then pagehide/visibility, explicit flush, teardown and host-suspend integration. This follow-up deliberately takes the safe deduplication/serialization fallback rather than claiming async coalescing is crash equivalent.

Deterministic tests in [`note-buffer.test.ts`](../tests/note-buffer.test.ts) use 16 distinct large snapshots, each delivered three times, with quotes, backslashes, newlines, emoji and a lone surrogate. Observed operation counts are 16 synchronous storage writes and 17 string encodings (one saved base plus 16 contents), with each edit recovered immediately before any scheduler advances. The previous path made 48 writes and 48 whole-object serializations, encoding the saved base and content on each. Payload characters written equal exactly the sum of the 16 unchanged-format JSON records; distinct-edit storage volume remains O(base length + content length). The cache saves repeated base escaping, not full-payload storage. Full editor document conversion, sibling synchronization and status scanning remain separate work.

Fake-clock tests prove duplicate snapshots preserve the original autosave deadline and disposal cancels later callbacks. Controlled storage/disk failures prove checkpoint retries at update/flush/dispose, failed-close draft preservation, clean-removal retry and fresh-buffer recovery. Controlled overlapping saves prove the checkpoint base advances before the next write; relocation assertions prove a new key receives a checkpoint and duplicate relocation does not repeat it. These are operation-count and state assertions, without timing thresholds or native latency claims.

Durability limits remain explicit: unavailable recovery storage can still fail, and disk/checkpoint updates are not one atomic transaction. The pre-existing save path can remove a draft when text reverts to `savedText` during an in-flight disk write; a crash before subsequent reconciliation is not covered by the existing eventual-save test. This optimization does not fix that broader save-state boundary or establish crash atomicity. Native close/background tests and a separate in-flight recovery design are still needed. The buffer/workspace suites pass 37 tests, and TypeScript plus whitespace checks pass for this follow-up; original static audit findings elsewhere remain snapshots.
