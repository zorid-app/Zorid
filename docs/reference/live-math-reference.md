# Math rendering reference and implementation boundary

This is an original implementation guided by static behavior evidence from the pinned Obsidian 1.14.4 distribution. No recovered implementation or assets are included. The shipped math engine is independently obtained from upstream packages. This report distinguishes verified contracts from remaining gaps; it does not establish complete Obsidian or native parity.

## Upstream package strategy

The root integrator owns package/lock changes: exact `mathjax@4.1.3`, `@mathjax/mathjax-tex-font@4.1.3`, and `@mathjax/mathjax-mhchem-font-extension@4.1.3`. Official registry metadata verified by the root reports publication on 2026-07-03 and unpacked sizes of 19,971,291, 9,267,774 and 96,205 bytes respectively. Runtime `mathjax` also depends on the default New Computer Modern font package; that package is installed transitively but is not emitted by this feature. No source-package dependency is needed.

The [upstream font documentation](https://docs.mathjax.org/en/latest/output/fonts.html) specifies local `loader.paths.fonts`, `-nofont` combined components, and promise-based conversion for asynchronous font ranges. The [upstream loader documentation](https://docs.mathjax.org/en/latest/options/startup/loader.html) describes component path prefixes. The [safe extension](https://docs.mathjax.org/en/latest/options/safe.html) filters TeX-generated URLs and styling. These APIs support a local component runtime rather than copying the recovered custom bundle.

`MathAssetsPlugin` from `scripts/math-assets.cjs` emits only runtime `tex-chtml-nofont.js`, TeX extensions, `ui/safe.js`, and the two fonts' CommonHTML data/fonts, with the upstream Apache-2.0 license and the font packages' license/version metadata (the published font packages contain no standalone LICENSE file). No source maps, SVG font data, alternate combined engines, or recovered assets are emitted. All runtime load paths are local `lib/mathjax/` paths. Root owns the webpack hook. The actual installed-package manifest and real engine were validated by `tests/math-engine.test.ts`: all component requests and every generated font stylesheet URL resolve to the emitted local assets (72 files, 1,540,566 bytes). The default combined upstream component includes menu code that resets enrichment from its own settings even when the menu is disabled; explicit disabled enrichment/speech/braille settings and clearing the engine's persisted menu key preserve the pinned desktop behavior. Configuration is created in the destination window's realm, required by upstream option handling for popouts.

## Integration contracts

- Add `liveMathMarkdown` from `src/editor/live-math.ts` to the existing Markdown parser extensions. It is the same export as `mathMarkdown` from `math-syntax.ts`, suitable for a Reading parser. `mathSpan(node, read)` returns unchanged source coordinates, TeX, display/layout flags and `closed`; incomplete blocks must not be rendered.
- Add `liveMath({excludes: renderedCalloutRanges})` when whole-callout rendering is installed. The optional callback returns ranges owned by other renderers and is reevaluated on every transaction, including state-only changes. Such exclusions take precedence over geometry freezing; no math widget may overlap a whole-block replacement. A focused combined-state test verifies source reveal and ownership changes without importing a callout module.
- Add `liveMath()` only in Live Edit and import `live-math.css` into the application stylesheet. The optional renderer argument exists for isolated tests and alternate hosts.
- Reading calls `renderMath(parent, tex, {display, onReady?})` from `src/ui/math-renderer.ts`. The returned `ready` resolves to whether the current parent received the result; `dispose()` must be called when a Reading section/embed is removed or replaced. A later invocation on the same parent also invalidates its predecessor. Detached parents are permitted during construction, so connection status alone is not used as a lifecycle signal.
- The shared loader starts once per owner document. Rendering is serialized per document, deduplicated and cloned into each output parent. The bounded LRU retains at most 128 expressions and 262,144 source characters, with no entry longer than 32,768 characters. Recognized macro/package mutation commands invalidate it and are not cached. This is an original bounded cache, not an assertion of exact reference caching semantics.
- Engine failures retain literal TeX and mark `math-error`; no note source enters executable HTML. MathJax safe filtering is complemented by a final DOM guard. Measurement callback exceptions do not invalidate a successful result. Disposal suppresses late DOM/measurement updates, though already queued engine work may finish.
- A per-widget ResizeObserver requests measurement after browser font/layout changes and disconnects on disposal. Stable widget identity survives source-position shifts and display-source reveal. All focused selections reveal intersecting expressions. Pointer and composition interactions freeze replacement geometry through their settling transaction. Clicks/edit controls resolve current positions by identity; links within rendered output retain their interaction. Unchanged parsed spans in a temporarily unavailable tail are retained only if source edits did not touch them.

## Verification and explicit gaps

Focused tests exercise real CodeMirror state/widgets in jsdom and an injected deterministic engine. They cover grammar ownership, escaped/incomplete syntax, Unicode ranges, source preservation, inline/display distinction, display-preview retention, multiple/reversed selections, moving source positions, undo/disposal, pointer/composition settling, cache bounds, queue ordering, loader retry, stale results, callback isolation and safe output. jsdom stubs geometry; it does not certify native caret hit testing, IME candidate placement, font metrics or screenshots.

The current grammar intentionally handles single-line `$...$` and `$$...$$` plus exact standalone document-level `$$` blocks. It leaves quote/list container fences, runs of three or more dollars, unclosed fences and Reading-only multiline inline forms literal. The pinned Reading parser supports additional forms and may render unclosed blocks; these are known gaps, not claimed equivalence. Table math remains owned by the table editor and is not replaced by this extension. Existing multiline `%%` comment parsing is a separate limitation of the shared Markdown grammar. This foundation does not add MathJax equation-reference coordination across note sections, a math context menu, or math-specific keyboard navigation.

The 35 focused tests include actual upstream execution of fraction, chemistry, cancellation/bold/bbox, package alias and unsafe-link expressions against emitted assets, with zero remote requests. Independent review also exercised additional physics/unicode expressions. Integrated Reading/Live wiring, native desktop rendering and mobile verification remain separate acceptance steps. Root owns integration/native checks. Do not mark this feature fully equivalent from these isolated tests.
