## Original implementation and explicit gaps

`src/ui/properties.ts` routes heading, row/type selector and list/tag/alias item context events through the platform `showContextMenu` service, using the owning document. ContextMenu and Shift+F10 work on focusable heading/rows and list inputs. Scalar/name inputs retain native text menus. Supported actions are heading Add/Sort/Clear, property Remove, and list Edit/Copy/Remove. Clipboard Copy is disabled when no clipboard writer is available. The shared platform descriptor has no warning/icon field, so warning styling is not reproduced.

The type submenu preserves the audited ordering, reserved-key rules and check states. Ordinary choices are local display preferences only. A choice is disabled unless the existing value already validates for that type; selecting it never writes or coerces YAML. Automatic removes the local preference. This deliberately does not claim parity with the missing vault-wide type registry or mismatch modal. The older type dropdown retains its separately existing conversion behavior; this change does not expand it.

Property clipboard selection/MIME machinery, extension hooks, mobile-specific title menus and linked-value context contributions remain absent. The existing `openLink(target)` callback cannot express new panes, target existence, file rename or missing-note creation. No misleading placeholder entries are exposed for those capabilities. Existing single-link activation remains unchanged.

New option fields are all optional: `showMenu`, `dismissMenu`, `writeClipboard`, `onError`, and `isCurrent`. The first two allow platform-service injection; `isCurrent` lets a host reject an action after file-owner replacement even when the visible data is identical. A host that reuses a panel must supply that guard or destroy the previous view. Rejections appear in the panel's alert and are forwarded to `onError` when supplied.

Each returned action revalidates its owner, connected row/item, unsaved draft and captured property value before acting. Mutations repeat the checks inside the serialized save queue. Header mutations compare the full property snapshot. New body edits and unrelated property edits are preserved where the action does not target them. A changed target is rejected rather than overwritten. Destruction invalidates pending selections and dismisses an owned popup; a later context event relinquishes ownership so teardown does not close another surface's popup. The current platform service has no popup ownership token: another surface opening a menu programmatically without a context event remains a platform-level ownership limitation.

`src/ui/property-menus.ts` implements original header mutations with the existing YAML parser/validation boundary. Sort reorders existing YAML nodes and retains styles, comments, unknown nested values, BOM, delimiters and Markdown body bytes; the serializer may normalize YAML spacing. Already sorted input is unchanged. Alias-before-anchor results and malformed source are rejected. Clear removes the frontmatter block and preserves the BOM and remaining Markdown body. These are data-preservation improvements, not claims that the reference's serializer is byte-identical.

## Verification

Focused Node/jsdom tests exercise exact supported menu ordering and availability, reserved type behavior, noncoercion, real browser fallback dispatch/dismissal, keyboard ownership, clipboard and persistence failures, delayed and queued stale selections, changed owner/disconnected/destroyed views, drafts, unrelated edits, comments/unknown data, CRLF/BOM/delimiters and invalid alias sorting. Native Electron, mobile gestures, visual parity, third-party extensions and reference runtime parity were not exercised by this task.
