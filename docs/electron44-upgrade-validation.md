# Electron 44 upgrade checkpoint

The user selected macOS 13+ and the latest stable Electron on 2026-10-16. The [official release list](https://releases.electronjs.org/) identified 44.8.0; the exact pin and frozen dependency graph now use that version. Electron 44 [requires macOS 13 Ventura or newer](https://www.electronjs.org/docs/latest/breaking-changes#removed-macos-12-support). Packaging and the generated Homebrew cask declare the same minimum. Historical Electron 31 native/reference observations remain dated evidence.

The change was prepared in an isolated worktree from `3fa19fc`, without replacing the main checkout's dependencies or runtime. Only Electron's dependency subtree changed in the lockfile. pnpm's minimum-release-age exception names the exact newly selected `electron@44.8.0`; it is not a blanket exception.

Electron 42+ [does not install its binary through postinstall](https://www.electronjs.org/docs/latest/breaking-changes#behavior-changed-electron-no-longer-downloads-itself-via-postinstall-script). After an explicit frozen dependency install, run `pnpm run desktop:install --arm64` or `--x64`. The bootstrap invokes the pinned package's installer directly, retaining its published checksum validation. It verifies version, CPU architecture, expected executable path and runtime notices before staging can succeed. The upstream [installer](https://github.com/electron/electron/blob/v44.8.0/npm/install.js) does not check architecture on its installed-version fast path and can override x64 under Rosetta; the bootstrap rejects an existing wrong-architecture binary and sets both architecture variables explicitly. Separate matrix installations avoid overwriting a runtime used by another process.

Observed locally:

- Frozen installation with lifecycle scripts disabled completed in the isolated worktree. The explicit bootstrap downloaded and verified the official macOS arm64 runtime and notices; it did not launch Electron.
- The focused desktop, broker, runtime, packaging, Homebrew and release tests passed with concurrency 1. TypeScript checking and a fresh production Webpack build passed; Webpack retained its existing size/performance warnings.
- An unsigned arm64 directory package passed the mandatory after-pack check and separate exact verification of all 328 staged files. The application was 320 MiB, including a 31 MiB ASAR. Its minimum-system plist value was `13.0`, its framework version was `44.8.0`, and its executable was Mach-O arm64.
- Local packaging reused the installed distribution through `--config.electronDist=node_modules/electron/dist`, avoiding a duplicate download. A temporary PATH entry selected the cached exact pnpm 12.14.0 executable because the machine's general launcher misrouted nested-worktree commands; no launcher workaround was added to the release workflow, which pins pnpm explicitly.

These are bootstrap, build and unsigned packaging results. Native Electron 44 editor/vault/media behavior, an Electron 44 DMG mount, x64, actual macOS 13 execution, signing, notarization and Gatekeeper still require their own evidence. Earlier Electron 31 smoke and DMG results do not satisfy those gates. No release tag, signing operation or publication was performed by this change.
