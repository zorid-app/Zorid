Implementable corrections / adversarial traces (contract line references):

1. Causal projection and creation (43-57): compare ancestry of writes TO THAT FIELD, not only global graph heads; unrelated later writes must not erase a field candidate. Define exactly one generation-create root and require every non-create operation to descend from it (edits arriving before create remain pending); reject a second distinct create for the same generation, or explicitly expose a create conflict. Trace C; A(parent C,title=a), B(parent C,title=b); X(parent A,color=red) => title conflict {A,B}; R(parents X,B,title=r) => only R, with A/B retained after export/reload. Include unset versus null and equal concurrent values. Define canonical ID ordering and operation-content equality rather than relying on map/JSON iteration order.

2. Set authorization (59-61): an observed tag must identify a specific add ACTION in the remove operation's causal ancestor closure, for exactly the same field/member/generation; presence anywhere in replica state is insufficient. If one patch can add multiple members, tag identity needs (operation ID, action ordinal), or each add must be its own operation. Trace concurrent A:add(m), R:remove(tag A) both parent C: reject R even if A arrived first; R(parent A) succeeds; concurrent B:add(m) survives R. Reject tag theft from another member/field/generation and duplicate conflicting actions. Scalar set/null/unset on a set field must be forbidden initially or receive explicit reset semantics; arbitrary array replacement cannot coexist ambiguously with OR-set history.

3. Pending activation/cycles/equivocation (46-47,67-71): pending entries must be included in duplicate-ID and cycle checks; receiving a parent must revalidate the entire newly activated dependency closure transactionally. Specify whether invalid pending descendants make that arrival fail or move to an explicit rejected/unresolved class, never silently publish them. Traces A(parent missing B), then B(parent A) => cycle rejected with prior state unchanged; pending R(parent P, remove wrong tag), then P => no half-published P/R; pending ID Q with payload x, then Q with payload y => conflict before dependency completion. Reverse every order and restore pending snapshots. Ordinary different-content ID equivocation across replicas is not a convergent union: report it as integrity conflict/unresolved rather than claiming first-seen-wins convergence.

4. Capacity is an explicit bounded-domain gate (103-109), not a convergent eviction rule. Trace 4095 common ops then concurrent A/B: each replica can admit its own 4096th, but their union is 4097; reject/retain unresolved observably and make no final-convergence claim, never drop a winner/history to fit. Count pending and unknown fields/tags/removed tags against total byte/count budgets, not just accepted/declared fields. A pending-filled budget must leave dependency arrivals observably blocked rather than acknowledge completion. Thirty-three concurrent heads exceed the 32-parent limit for a resolving write; either add bounded merge-only causal operations or explicitly report that write precondition instead of silently omitting heads.

5. Bound/canonical decoding (102-110): define aggregate canonical snapshot bytes as well as incoming batch bytes, field/action/member/tag/parent counts, JSON nesting including arrays, string/key limits, duplicate JSON keys and duplicate field actions; reject integer overflow/nonfinite and noncanonical or ambiguous encodings before state publication. Trace many individually valid <=16KiB operations whose union exceeds 1MiB; deeply alternating arrays/objects; duplicate op keys; 65 unknown fields under a 64-declared-field schema. Exact ciphertext framing overhead belongs to the later protocol gate, so do not claim a full 1MiB logical snapshot automatically fits the relay limit.

6. Unknown fields/version compatibility (94-100): preserving unknown fields requires a concrete additive-compatibility rule; rejecting every schema-version-greater-than-local operation contradicts that acceptance case. Separate understood additive field-schema versions from unsupported semantic/action versions, retain remote typed unknown writes and OR-set actions, and forbid local unknown writes. Trace v2 optional field U scalar/object/set, offline v1 known-field patch/unset, merge/export/reload => U intact; incompatible known-field type or unsupported action version => no partial application/progress. Required/default rules also need deterministic validation: local create encodes defaults once; replay never supplies them; required-field unset is rejected.

7. Delete/restore (17-20,63-65): include an immutable restore-source generation/tombstone reference in new-generation creation and validate that link at the host boundary, since one-generation documents cannot prove another generation's deletion by themselves. Trace delete G and concurrent edit G; create H restored-from G; late delete/edit G => H unaffected and G history exportable. Two concurrent restores H/I remain distinct; no implicit single-live-generation selection is promised. This does not require cross-record atomicity or block portable source progress.

8. Planner/trusted policy (12-15,114-121): bind prepared state to complete scope, exact base causal revision INCLUDING pending/history/delete changes, trusted registration/schema/policy revision and authored operation identity; never accept a serializable caller plan as authority without validation/recompute. Trace prepare at v1/synced, host changes to local or revokes owner, then commit => reject with no state/outbox/change/cursor effects; incoming duplicate exact receipt => no duplicate change event. Read/query/export/subscription authorization remains a host obligation from the reviewed draft. Pending causal dependency acceptance and unsupported-version quarantine are different statuses, each requiring an explicit later dispatcher receipt/cursor policy.

Optional later work, not source blockers: compaction/history externalization, multiple-generation UX, richer migrations and isolated-plugin capability design. The bounded portable slice is not complete durable sync or representative long-lived review history; the contract already records those later gates.
