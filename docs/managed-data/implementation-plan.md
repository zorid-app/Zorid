# Managed-data feature planning entry point

Updated 2026-10-21. Use the [Bases implementation goal](../plans/bases-implementation-goal.md) for the
current local feature scope and acceptance. The [roadmap](../roadmap.md) owns
delivery order; the [execution checkpoint](../deferred-product-roadmap.md) owns current
assignments, integration authority and verified results.

The earlier combined plan and assignment sequence are superseded. Bases use
ordinary files/properties; `type: book` is optional user data. Named note Types
and a Type registry/editor are removed from the target, while rich property
definitions remain in scope. The current goal records the Obsidian 1.14.4 initial
appearance/interaction target and the literal full-template-copy exception.

Tasks, Calendar/planning, Google two-way integration, sync, native mobile and
recovery/administration remain later roadmap requirements. Their earlier Type
and managed-record assumptions require reconciliation when resumed. Public
plugin APIs remain a discussion topic; spaced repetition was removed. This
routing update does not remove existing source, migrate data or establish feature
acceptance. New source ownership must be assigned through the current checkpoint.

The [original committed snapshot](../history/managed-data-implementation-plan-20261017-superseded.md) preserves the old design and
receipts for provenance. Historical assignments are not active source grants.
