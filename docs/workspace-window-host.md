# Native window workspace host

The first host stage wires an actual empty native window command and independent persistence. It does not transfer a tab or reopen a file as a substitute for transferring its state.

The authenticated desktop bridge provides `getWindowInfo(): {id, initialState}` and `newWindow(): {id}`. The primary window has the stable ID `main` and restores its session. Additional windows receive unique IDs and `initialState: 'empty'`. The native broker, not a URL/query string or renderer-selected value, supplies identity and inherits the caller's vault grant. Identity lookup failure or malformed data aborts workspace initialization. Uniqueness among live windows is a native broker responsibility; one renderer cannot establish that another renderer has not been assigned its ID.

`Cmd+Shift+N` on macOS and `Ctrl+Shift+N` elsewhere invoke the native command, including from an empty vault picker. The exact modifier matcher also handles numbered tabs, new tab, and new file. A new-window chord without native capability is consumed without creating a note. The command palette exposes “Open new window” only when the native capability exists. No save, tab removal, or source editor mutation is needed to open an empty window.

`WorkspaceStorageScope` namespaces sessions and recovery drafts by encoded window ID and vault ID. Browser/mobile deployments without the native capability retain their existing keys. A fresh native window has a newly allocated identity and therefore no session to restore. Reloading its renderer restores the existing same-ID session even though its creation metadata still says `empty`. The primary window alone migrates old single-window session and draft keys by copying before removing originals. Failed writes preserve the old bytes and abort vault replacement before an empty session can overwrite recovery. Only a canonical encoded note-path suffix qualifies, preventing a colon-containing longer vault ID from matching the wrong legacy prefix. A completion marker prevents stale legacy drafts from reappearing after a newer scoped draft has been saved. Divergent pre-existing scoped and legacy drafts are both retained; the legacy copy remains available for manual recovery and is not reapplied automatically.

Shared-file conflict protection belongs to the desktop adapter's atomic compare-and-write operation and cross-window change notifications. Recovery isolation does not itself merge simultaneous edits. The native lane owns those operations and sender validation. Ephemeral extra-window IDs are deliberately not advertised as cross-restart restoration: restoring those windows requires a future native window manifest/recovery discovery policy. Their draft bytes remain stored under the original identity.

Validation uses the real workspace with an injected DOM editor: window shortcut dispatch, empty initial state, scoped draft writes, subsequent same-window restoration, identity failure, migration, conflicting legacy retention, and quota failure. Keymap tests cover exact modifiers and unavailable commands. Native window appearance and OS shortcuts still require the parent integration's Electron verification.

Tab edge docking and same-object editor/view retention are the next distinct host stage. Full tear-off requires the validated two-phase handoff contract and destination-ready acknowledgement; source authority must remain until commit. See `tab-docking-reference.md` and the window-handoff contract documentation.
