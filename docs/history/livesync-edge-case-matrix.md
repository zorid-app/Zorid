# LiveSync edge-case matrix

Audit date: 2026-10-16 America/Toronto (2026-10-17 UTC). This is a bounded source audit requested by the user, not an exhaustive inventory of every LiveSync fix or a claim that Zorid has reached sync parity.

## Pins and evidence boundaries

- Self-hosted LiveSync: `72dc88c7efe46a67cf0bfaa29864b39e59b4fcbc` (1.0.37 merge).
- livesync-commonlib: `5f79422c96565ee33f26449668cda2f6d67376f7` (0.1.41 merge). This preserves the previous audit pin in [the roadmap](../deferred-product-roadmap.md#applicable-livesync-reference-invariants).
- Zorid source baseline: `149b908b3a3d12b48f365a244658a9b2ff23f61c`, canonical main when this isolated documentation worktree was created. Paths below are relative to that tree. Later work must update the coverage column against its actual integration SHA.
- Inspected: storage event/offline/provenance contracts, conflict and garbage-collection designs, chunk retrieval/retry tests, RPC implementation/tests, P2P lifecycle/tests, recent release notes, selected encryption/startup tests, and issues #1168, #1224 and #1234. Test names were located and selected representative bodies inspected; not every test body or implementation branch was audited.
- No upstream or Zorid tests, builds, browser apps, databases, or servers were run for this audit. **Source test present** below means an exact regression exists in the pinned Zorid source, not that this audit observed it pass. In particular, portable/native tests do not establish real web/Electron editor, native watcher, mobile, or P2P acceptance.
- Upstream links are commit-pinned. Issue pages are mutable observations from the audit date. Upstream design documents and compatibility behavior can describe limitations as well as solutions; those distinctions are retained below.

Priority: **P0** before enabling the relevant sync/data-loss path; **P1** before its production release; **P2** deferred transport/maintenance work that must remain disabled until its gate is met. A P2 feature can contain P0 integrity requirements when implemented.

## Decisions and acceptance work this audit implies

1. Keep one durable authored/received protocol across web, Electron, CLI and eventual P2P. A received commit has no authored outbox; a local filesystem projection is a separate recoverable obligation. ACK-1, PROV-2 and ORDER-1 have useful native tests but still need real web/Electron editor acceptance.
2. Before enabling distributed files/binary data, implement and verify DEL-2, NAME-1/2/3 and CHUNK-1/2/3 together. Include three replicas, offline edits, partial manifests, process death and missing chunks; retain alternatives rather than hiding failures behind a sync-complete label.
3. Keep GC and retention-based pruning disabled until GC-1/2 have an explicit safe-rejoin policy and tests. Backup existence is insufficient without decryption keys, retained format support and a tested restore path.
4. Exercise real client lifecycle: checkpoint failure, ambiguous prepare/commit ACK, duplicate tab/window ownership, DB replacement, IME/draft/undo preservation and cross-client notifications. Host/portable tests are prerequisites, not substitutes.
5. Treat upstream issue reports as regression seeds, not certification. #1224 has delayed-arrival tests but unresolved original/permanently-missing variants; #1234's confirmation was partial; #1168 remains a native filesystem acceptance scenario. Preserve these limitations in follow-up results.

## Unresolved audit scope

This pass did not enumerate every historical issue/PR or all changelog versions. It did not audit CouchDB/PouchDB internals, MinIO multipart consistency and journal compaction, full P2P wire authentication, TURN implementations, every mobile suspension path, all encryption migrations, plugin settings/customisation storage, selective-sync product semantics, filesystem Unicode normalization on real volumes, large-vault scheduling or every upstream security fix. The local clone contains related fixtures, but discovery is not review or execution.

Follow-up audits should be assigned by boundary before its implementation ships: object storage/chunk lifecycle; deletion/history/GC and safe rejoin; native watcher/path portability; P2P admission and cancellation; encryption/recovery/migrations. Update this matrix with exact integrated Zorid SHA and observed evidence, keeping implementation and verification separate.
