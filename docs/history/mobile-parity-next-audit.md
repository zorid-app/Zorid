## Proposed small patch, before implementation

**Preserve the platform text menu for ordinary inputs when the native desktop menu bridge is unavailable.** Own `src/ui/workspace.ts`'s `inputContextListener` and a focused `tests/workspace.test.ts` regression. Return before calling `showContextMenu` when the input's owner window lacks `zorid.showContextMenu`. Keep the current desktop bridge path.

The confirmed code defect is that a non-desktop input context event is canceled and replaced by a menu which can offer no usable Paste command. This is not a claim that a particular Android or iOS WebView was observed delivering that event. The fix restores the browser/OS opportunity to provide its native menu, whose native behavior remains a device test.

Acceptance checks: (1) no bridge plus input/textarea context event remains uncanceled and creates no custom menu; (2) a bridge receives existing ordered input edit roles; (3) checkbox/range remain excluded; (4) existing editor/table semantic menus are unaffected. Test selected and empty inputs, title/search/property fields, and owner-document handling. Read-only text inputs should also retain native selection/copy. Do not weaken clipboard permissions or emulate Paste with an unrequested asynchronous clipboard read.

This small patch does not resolve editor contenteditable menus, whose format/table commands require a deliberate mobile design and reference test. It was proposed before implementation; the follow-up below records its current status.

### Bounded implementation follow-up

`src/platform/input-context-menu.ts` now exports `shouldOverrideInputContextMenu(input)`, which requires a callable `showContextMenu` on the input's owning window. It uses neither user-agent nor viewport guesses and performs no native call. Three focused tests pass with `node --test --test-concurrency=1 tests/input-context-menu.test.ts`, covering absent/partial/non-callable bridges, ordinary and read-only controls, document adoption across differently capable windows, and documents without windows.

Workspace integration is assigned separately: import the helper and return immediately after the existing input/checkbox/range guard when it returns false. At this follow-up checkpoint that wiring and its actual event-level regression are still pending; the helper tests alone do not change live behavior or close the finding. Native long-press/paste validation remains open after integration. Other mobile gaps remain queued without implementation changes.

## Dependency order for subsequent patches

1. Preserve native ordinary-input menus, then perform paired keyboard/selection/clipboard observation. This creates a reliable basic text-input route with a small blast radius.
2. Add a platform capability/state boundary for native platform, keyboard visibility/heights, physical keyboard, app state and viewport/insets. Make teardown and stale-event handling explicit. Retained reference method names exceed stock plugin APIs; any custom native implementation needs its own contract rather than an assumed npm substitute.
3. Implement editor-focused mobile toolbar and caret visibility on the measured coordinate system. Cover nested table editors and split panes; prevent toolbar presses from losing the editing target. Separate tablet/native identity from width-only CSS. Verify safe-area ownership before changing automatic insets.
4. Add touch menu placement/activation and table-grip pointer support after paired gesture evidence. Preserve row/column/multiple-selection semantics and read-only guards. Test cancellation, scrolling, submenu edges and stale selections; do not apply `touch-action: none` to whole notes.
5. Add mobile vault create/open/recent flow with a provider-aware adapter identity and durable grants, then attachment picking/share/URL routing. Keep app-local vaults usable, honor cancellation, and reject inaccessible roots/providers visibly. Validate collision rules and persistence before multi-vault rollout.
6. Add lifecycle save requests and back/navigation handling with recoverable pending writes. Measure background/resume/process-restoration outcomes; no OS-completion guarantee should be claimed from a listener alone.

These steps preserve the full editor, split-view, onboarding and context-menu scope. Native shares, URI handling, provider grants, widgets/tiles, accessibility, binary persistence, conflict behavior, plugin APIs and performance remain open even after these patches. Deferred sync and calendar/task feature work is unchanged.
