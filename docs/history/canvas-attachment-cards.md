# Canvas attachment cards

`createCanvasAttachmentCard` is an original internal adapter for resolved vault file paths. Canvas hosts retain its owner by node ID, path and subpath and destroy it when that identity changes. It reuses `createImageView`, `createPdfView`, `createMediaView` and the host's shared `AttachmentResources`. It does not acquire an additional outer lease or destroy shared resources. Markdown file cards have a separate host renderer.

Import `src/canvas/attachment-card.css` alongside existing viewer styles. The helper fills the supplied card container; explicit `resize` is optional. Image/video content fits the available area. PDF uses embedded controls with automatic height disabled by fixed-card CSS; the existing PDF stage resize observer updates its layout. PDF fragment navigation is preserved, while fragment-specified embed height cannot override Canvas geometry.

Image readiness means resource acquisition, PDF readiness means shared viewer initialization, and media readiness follows the shared metadata/error/timeout contract. None guarantees visible pixels or playable codecs. Destruction settles readiness immediately, releases current leases and releases late acquisitions. Fresh byte reads revalidate lifetime after awaiting. The helper clears the shared image viewer's retained click property at disposal to prevent detached images reopening a lightbox. Viewer and acquisition failures remain visible; host diagnostics cannot interrupt cleanup.

Thirteen focused tests exercise the real shared image/audio/video DOM lifecycles and an injected PDF adapter boundary, including source selection, fragments, cancellation, late failures, retained controls, failed construction, fresh bytes, resource counts and sizing inputs. TypeScript checking passes. This is integration implementation evidence, not new reference evidence or pixel parity: no reference execution, native Canvas interaction, PDF layout measurement, media codec playback or mobile verification was performed in this lane. Native/visual verification remains required. Existing bounded reference evidence is in `canvas-reference.md`, `canvas-style-reference.md`, `pdf-reference.md` and the shared attachment/viewer audits.
