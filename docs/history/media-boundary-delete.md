# Audio layout when removing an adjacent newline

Native investigation distinguished source loss from a layout failure. With `# Media verification\n![[Native media tone.wav]]\n\nAfter audio.\n`, Backspace at the embed's source start removes the preceding newline and joins the intact embed marker to the heading. The embed then uses an inline wrapper. That wrapper previously had shrink-to-fit width, while the nested audio control used percentage width, leaving the control too narrow to expose its usual playback controls. The apparently blank caret row above the block player is not necessarily an empty source line.

The targeted fix gives only inline wrappers containing `.audio-embed` a definite available width (`width: 100%; max-width: 100%`). Audio still uses its existing full-width, 42-pixel-high control. Images and other inline embeds retain their existing sizing rules. No editor command, Markdown source, embed API or workspace behavior is changed.

Retained Obsidian 1.14.4 `app.css` at decoded character offsets 331721–331900 specifies rendered audio `max-width: 100%` and general audio `width: 100%; height: 42px`. Its SHA-256 is `866e50ac84dd8ad2775e0047ebd3ec5bd03e5af722aff259e6c4ea3cec42d7ba`; the retained artifact/extraction evidence chain is in `live-callouts-reference.md`. This supports retaining the audio control's percentage sizing; the wrapper constraint is an original host-layout repair, not a claimed reproduction of every reference wrapper rule. No recovered source is copied.

Focused real-CodeMirror/jsdom tests cover Backspace and forward Delete on empty source lines before and after the media, joining an embed directly to a heading or plain prose, exact source edits, undo/redo, surviving controls and balanced renderer ownership. A CSS applicability check confirms only the inline audio wrapper receives the new width; an explicitly sized image is unchanged. These tests do not establish native pixel dimensions or usable native controls. Root owns native wide/narrow-pane and image comparison after integration.

Some CodeMirror block-boundary changes remount the embed, including a block-to-inline transition and forward deletion from the empty line before it. Resources are released once and one rendered child remains live, but playback may reset at those remount boundaries. Ordinary unchanged-widget cursor movement and source-position shifts retain existing identity coverage. Avoiding every remount is outside this layout repair.
