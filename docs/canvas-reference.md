# Canvas document reference and original model

This is a bounded static investigation of Canvas document loading and data serialization in the supplied Obsidian 1.14.4 desktop artifact. It does not establish complete rendering, interaction, history, persistence scheduling, clipboard, file resolution, embedding, export or plugin parity. The original interactive subset below is implemented and event-tested separately from those parity claims. The reference application was not executed. No recovered code or assets are included in the project.

## Original implementation contract

[`src/canvas/document.ts`](../src/canvas/document.ts) is a standalone JSON data model. The companion `src/canvas/view.ts` consumes this model without changing hidden source records; application routing is owned by the integration layer. `CanvasDocument.parse` exposes immutable `nodes`/`edges`, ID lookup, root-field lookup and `toString`. Node/edge add, patch and remove operations, root edits and endpoint-aware node renaming are available to a future integration.

The following are deliberate original choices, not claims of observed reference behavior:

- Unmodified input is returned exactly, including whitespace, line endings and empty input. `{}` and missing arrays remain unchanged while getters expose empty lists. JSON whitespace alone and BOM-prefixed input are rejected by standard JSON parsing. On semantic no-op edits both source and snapshot identities remain unchanged.
- A successful edit serializes the complete JSON object using the detected indent and line-ending convention, preserving whether it ended in a newline. Field values and unknown root/node/edge data remain; original numeric spelling, escape spelling and spacing are not preserved after edits. Standard JavaScript JSON number and duplicate-object-key semantics apply: numbers use binary64, and the last repeated object key wins in the parsed model. Unedited source still remains exact. This is a string model, not a byte decoder for malformed UTF-8 files.
- Root must be an object. Present nodes/edges must be arrays. Node IDs/types must be nonempty strings; geometry must consist of finite numbers. Recognized text/file/link types require string text/file/url respectively; optional known fields must be strings. Color, side, marker and background-style strings are retained verbatim, including future values. Unknown node types remain accessible and serializable.
- Default parsing now retains duplicate IDs and dangling endpoints as raw records. `parse(source, { strictReferences: true })` enables the previous rejection behavior. A node and an edge may share an ID, and self-loops are accepted. The view projects renderable records separately rather than silently deleting source records. This supersedes the initial strict-only model choice.
- Coordinates are not rounded; no positive-size restriction, color conversion, missing side inference, marker default insertion or file/URL validation is invented at the document layer.
- Shallow patches preserve unspecified fields; `undefined` deletes a field if the resulting document is valid. Changing a node ID uses `renameNode`, which rewrites all endpoint references atomically. Removing a connected node requires explicit `{ removeEdges: true }`; otherwise it fails without changing data.
- Edits are staged, validated and serialized before publishing. Failures leave both source and immutable snapshots unchanged. Snapshots and caller inputs never share mutable objects. Plain JSON data is accepted; cyclic values, sparse/named arrays, nonfinite numbers, accessors, conversion hooks, symbols and non-plain objects are rejected. Prototype-like own keys remain ordinary data.

[`tests/canvas-document.test.ts`](../tests/canvas-document.test.ts) verifies unchanged-source roundtrip, all four built-in types plus an unknown type, retained fields after real edits, CRLF formatting, node rename/self-loop behavior, explicit cascading deletion, edge reconnection, empty input, input/snapshot isolation, unsafe values, duplicate IDs, dangling edges and failure atomicity. Validation now includes the companion view event tests described below.

Still unresolved: reference runtime error presentation and recovery, malformed field coercion beyond the inspected setters, node/edge lifecycle interactions, UI ordering, save/history/undo behavior, all rendering, export, embedded files/web content and Canvas plugin integration. This document closes only the original document-model work described above.


## Interactive view follow-up

The same hash-bound source was read at these additional character ranges (no target execution):

| Range | Static observation |
| --- | --- |
| 3304308–3304760 | History supports undo/redo, truncates redo entries on push, and applies a bounded history size. |
| 3317375–3318980 | Applying history imports data, replaces stored data and requests a save. Pan and zoom maintain separate viewport state. |
| 3334697–3335900 | Escape deselects; non-repeating Delete/Backspace deletes only when the wrapper owns focus and no drag is active. Middle-button dragging pans; primary background dragging selects. |
| 3343705–3344860 | Wheel line/page units are scaled by 40/800; modifier/space selects zoom under the pan default; ordinary wheel motion pans. |
| 3368426–3369000 | Primary mouse dragging moves selectable nodes; click selects exclusively and shift-click toggles selection. |

`createCanvasView(parent, options)` in `src/canvas/view.ts`, styled by `src/canvas/view.css`, implements an original interactive subset. Options contain `document`, asynchronous-or-synchronous `onChange(source, snapshot)`, optional `openFile(path, subpath)`, `openLink(url)`, and `onError(error)` hooks. The result exposes `element`, a `document` getter, `setDocument`, `undo`, `redo`, `flush` and `destroy`. Hook calls use exact stored paths/URLs; the view never fetches or embeds external content automatically.

Raw source and render state are separate. The projection retains the first supported class for a repeated node ID, merges later data and uses the final record index for editing. Nodes of unknown types and edges without projected endpoints are hidden, with a visible retained-record count. Duplicate edge IDs resolve to the last connected record, or disappear from the projection when a later same-ID edge is dangling, consistent with the inspected import map flow. Source order, duplicates, hidden objects and unknown fields remain intact after unrelated edits. Explicit deletion removes all records bearing the selected ID and incident edges; undo restores the exact prior source. Projection is an original approximation of setter accumulation, not a complete reimplementation of subtype coercion.

The surface renders literal text cards, file/link buttons, group containers, SVG edges with labels/colors and default arrow ends. It supports card creation and text editing, pointer/shift selection, background rectangle selection, movement, middle-button/space panning, wheel panning and modifier zoom, fit/zoom controls, edge/node deletion and undo/redo. Drag previews change existing selected node elements and connected edge paths only; release commits one model transaction, and pointer cancellation restores the preview without saving. Save hooks are queued in order, failures remain visible, and later changes are still deliverable. `flush` commits active card text, waits for the latest queued write and rejects if that write failed, so the host can keep the view open. Unsaved source remains in the model; a later `flush` retries it, and concurrent flush calls share that retry. New edits remain queueable after a failure. `destroy` only tears down controls and never initiates a write; the host must successfully await `flush` before closing or switching documents. Retained controls cannot mutate or open content after destruction. `setDocument` resets view history; viewport pan/zoom never modifies source.

Original subset choices, not full reference parity: straight edge segments instead of reference routing curves; simple side inference; literal text instead of Markdown preview; file/link title controls instead of embedded documents/web views; groups without background-image loading; bounded 0.1–4 zoom; a pan-default wheel mode; and an original toolbar. Resize, edge creation/reconnection controls, group-contained movement, snapping, arrow-key nudging, viewport persistence, touch multi-pointer gestures, keyboard shortcut registration, clipboard, export and the full reference menus are not implemented here. Geometry projection rounds finite positions/sizes for the view, while unchanged raw numbers remain exact in the source string.

Tests exercise actual DOM event dispatch: retained-data projection, hooks, drag previews and one-save release, atomic multi-node movement, cancellation, pan/zoom isolation, zoom-scaled coordinates, edge deletion, box selection, text commit/cancel, card creation, keyboard delete/undo/redo, exact source restoration, duplicate-ID edits, ordered asynchronous saves, surfaced failures, external reload and cleanup. Model tests additionally cover permissive/strict reference modes and multi-edit failure atomicity. Validation: `node --test tests/canvas-document.test.ts tests/canvas-view.test.ts` (28 passed) and `npm run check`. Lifecycle regression tests additionally verify active-editor flush, failed-save rejection and retry, queue recovery after newer edits, and inert retained controls after teardown.
