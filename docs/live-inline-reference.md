# Live inline source reveal and interaction

This report records the 2026-10-16 focused static evidence and the original `src/editor/live-inline.ts` implementation. It narrows the earlier regex preview's gaps without claiming complete Obsidian editor, Markdown, visual, security or OS parity. No reference application code was executed, and no recovered implementation or assets were copied into project source.

## Integration contract

The module exports:

- `liveInlineMarkdown`: a Markdown extension added to the existing `markdown({ base: markdownLanguage, addKeymap: false, extensions: liveInlineMarkdown })` configuration.
- `liveInline({ open, isUnresolved, onHover })`: a CodeMirror extension installed only in Live Edit. The optional `open` callback receives `(target, kind, event)`, where kind is `wiki` or `markdown` and event is the original mouse event.
- Optional `isUnresolved(target, kind)` supplies metadata resolution for wiki targets. The workspace captures the current source path; for example, return `!metadata.resolveLink(sourcePath, target, kind)`. The target retains its heading/block fragment; the existing metadata resolver strips the fragment for file lookup. Omitting the callback leaves resolution unknown, not falsely unresolved.
- `refreshLiveInline.of()` invalidates current decorations after metadata changes, without changing document/selection/history. The host must dispatch it to affected editors after create/delete/rename/index changes. Ordinary document edits also refresh resolution.
- Optional `onHover(target, kind, event, targetEl)` reports entering a wiki span, both rendered and revealed, using the current parsed target. It preserves the original event and does not consume it. The workspace owns preview settings, modifier requirements, delay and popup content; no generic browser title tooltip is added.
- `live-inline.css`: original styling loaded by the application, separately from TypeScript so source tests do not require a CSS loader.

Replace the old regex preview plugin and its heading decorations together. Remove the old regex Ctrl/Meta wikilink event handler to avoid a second navigation path. Keep the existing base syntax highlighting, list/task, embed, properties and table extensions. This module deliberately excludes code blocks, raw HTML nodes, tables, image nodes, wiki embeds, definition blocks and the valid frontmatter region. It does not decorate list markers or task brackets.

The grammar introduces `LiveInlineComment` for complete single-line `%%…%%` comments. **The existing embed scanner must add this node name to its excluded-node set**, so embedded syntax inside comments cannot mount while the comment is hidden. `LiveInlineWikiEmbed` remains owned by the existing wiki-embed scanner. Root/application integration is separate from this module's isolated tests.

The workspace owns navigation, path resolution, creation of missing files, background/new-pane disposition, protocol launching and context menus. The extension never assigns a note-provided URL to an HTML anchor and never calls `window.open`. The callback preserves Ctrl, Meta, Shift and mouse-button information. A wrapper that discards the event cannot claim disposition parity merely because the extension supplied it.

## Implemented behavior

The shared incremental syntax tree supplies asterisk/underscore emphasis, strong emphasis, strike, inline code, escape, link and heading boundaries. Original inline parser extensions add wikilinks, paired single-line comments and two-equals highlights. Nested groups retain their own source ranges. The module applies marks to actual editable source text and replaces only hidden punctuation or destinations; it never saves rendered text back into the note.

Unfocused editors show rendered inline content. Focused selection overlap, including token boundaries and multiple/reversed ranges, reveals the containing group. Enclosing formatting or link groups reveal their nested markers together. Other same-line groups stay rendered. Heading markers and escapes use line-level reveal. Active search-panel matches also reveal overlapping syntax while the search field owns focus. Source selections and history are not rewritten by decoration refreshes.

ATX headings receive level-specific line styling and hide opening/closing markers when inactive. Setext headings receive heading styling and hide their underline characters while keeping the actual source line. Inline code hides matched delimiters and preserves literal code contents. Incomplete delimiters remain visible because no valid syntax group was produced. Comments disappear only when a complete supported inline comment exists outside code/escapes; entering their source range reveals them.

Wikilink aliases are ordinary editable alias text, without interpreting their contents as nested Markdown. Local targets normalize NFC/nonbreaking spaces; direct Markdown destinations decode punctuation escapes, entities and local URI escapes. Markdown labels keep nested formatting. URLs are re-resolved from the current syntax tree on interaction, not trusted from stale DOM attributes after a concurrent edit.

Plain-click routing remains the reference-informed rendered-label behavior described above. Faint source brackets are editable, not an extra clickable widget. The underlying editable source retains aliases, targets and brackets unchanged. Hover preview policy must be supplied by the workspace; hover color and opacity are CSS behavior independent of a preview callback.

Plain left click follows only a currently rendered link label, excluding Alt/Shift clicks, overlapping noncollapsed selections and interactive/nested-editor targets. Revealed label/source text remains available for caret editing. Ctrl/Meta clicks can follow supported source tokens, and middle mousedown follows once. No DOM URL navigation is enabled. Dangerous/unsupported schemes produce nonnavigating marks. Current supported navigation is local links plus HTTP, HTTPS and mailto; custom protocols, file links and application deep links remain a platform-policy gap.

A capture listener freezes decorations before primary-mouse hit testing. Freeze persists through the release-to-click interval and ends on a delayed refresh. The extension maps its marks and hidden marker ranges through intervening transactions. Composition similarly preserves existing decorations until completion. Timers consult current state and are cancelled on destruction. Hidden punctuation is supplied through CodeMirror's atomic ranges for native movement; the extension itself does not snap, invent or asynchronously restore source selections.

All custom output is ordinary span/line decorations. Note HTML remains source text, not executable DOM. A tightly validated entity token may be decoded in a detached textarea, and the resulting URL undergoes separate protocol checking. This does not implement the reference's sanitized HTML widgets or certify all host protocol policies.

## Validation and remaining gaps

`tests/live-inline.test.ts` has 22 tests exercising real CodeMirror parsing, state, selection, history, decorations and DOM under jsdom. It covers nested formatting; focus/group/boundary/multiple selection reveal; headings; aliases and Unicode; code/HTML/embed/table/frontmatter ownership; comments; plain/modifier/middle link events; unsafe URLs; current-target lookup after edits; pointer freeze and subsequent source insertion/undo; composition; search reveal; and teardown cancellation. Added wiki checks cover unknown/resolved/unresolved metadata, missing-link navigation, metadata invalidation without history/selection changes, faint source punctuation, unaliased local headings, current-target hover with containment/interactive exclusions, and stylesheet selector application for rendered/source/unknown/missing states. The CSS checks assert declared theme-variable values, not browser color resolution or screenshots. These tests preserve and assert the Markdown source instead of inferring correctness solely from DOM text.

### Viewport traversal follow-up

The initial implementation checked every top-level block for each visible range and eagerly collected every direct child of a visible paragraph. The follow-up uses Lezer's `childAfter` seek at each parent, stops at the visible range end, and deduplicates children reached through multiple ranges. The installed Markdown parser balances large child sequences, allowing these seeks to skip unrelated blocks and inline children. Traversal still enters the containing top-level block and all relevant ancestors: a formatting group or heading beginning above the viewport retains its complete source/reveal decision. Inclusive boundary checks remain unchanged. Direct Markdown destinations are inspected from the tail of their link node instead of scanning all formatted label children. Generic containers no longer copy their entire source text during link classification.

Four added tests cover this delta. A refresh near the end of 100,000 blocks is limited to fewer than 120 public syntax-navigation operations (24 observed); a narrow range in a link label containing 2,000 formatted children is limited to fewer than 150 (29 observed). These are deterministic traversal-operation bounds, not machine timing assertions. The tests use controlled visible ranges because jsdom has no real scrolling geometry. A long multiline emphasis fixture verifies ancestor reveal from an off-viewport selection and deduplication across overlapping ranges. A controllably paused parser verifies that an incomplete viewport maps existing decorations through edits, then rebuilds after parsing catches up. The paused parser still honors `stopAt` completion, as CodeMirror requires.

This optimization changes traversal, not pointer, composition, selection, history or interaction timing. The operation counts exclude parser work, Lezer's internal seek implementation, source-target decoding and DOM measurement. A visible enclosing group may still require its full delimiter/target or line-boundary work; large visible ranges, many search matches and very deeply nested syntax retain their corresponding costs. No general frame-time, large-note typing-latency or reference performance equivalence is claimed.

jsdom's geometry stubs only permit the editor measurement scheduler to run. They do not certify browser pointer coordinates, native selection, font metrics, zoom, soft wrapping, bidirectional hit testing, accessibility, real IME, touch, or OS navigation. A real-browser scenario must click rendered text adjacent to hidden markers, type at the chosen location, and assert the resulting source offset. Repeat with dragging, Shift selection, wrapped lines, scrolling, different fonts/zoom, rapid successive clicks, images and nested table editors.

Remaining implementation gaps include reference-style links, footnotes, math, tags, block IDs, entity display replacement, highlight colors/longer delimiter runs, block or unterminated comments, further pretty display of unaliased heading fragments, empty alias behavior, full inline-code whitespace normalization, and native link hover popup/context menus/drag payloads. Multiline source breaks are preserved: ViewPlugin replacements do not remove line breaks, so hidden multiline destinations and setext underlines can leave their source line height. Touch selection uses CodeMirror's ordinary behavior; no reference touch-lifecycle equivalence is claimed.

Lezer's grammar and original extensions are not assumed to be identical to HyperMD's token grouping. Heading sizing remains original CSS; the focused wiki styles now follow the retained theme-variable contract but have not been compared against reference runtime pixels. The reference's complete modifier disposition rules, external-link affordance widgets, selection adjustment details, incremental performance and all malformed-syntax cases remain unresolved. This work is a focused editor foundation, not completed Live Preview parity.
