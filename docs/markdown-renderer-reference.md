# Markdown reading renderer: Obsidian 1.14.4

Snapshot: 2026-10-16. The inspected reading renderer parses a recursive Markdown tree, applies application extensions, converts it to HTML, sanitizes that HTML, and runs asynchronous DOM postprocessors. Zorid's current `src/ui/markdown.ts` uses a line loop and a single inline regular expression. These are materially different rendering contracts. This report specifies evidence for an original implementation; it does not establish complete Markdown, plugin, security, visual, or runtime parity.

## Lists and tasks in reading mode

The list tokenizer at 7,000–10,100 accumulates items according to indentation, marker kind, continuation lines, blank lines and interruption rules, then recursively block-tokenizes each item. Ordered lists retain their starting number; HTML conversion at 1,420–1,770 emits `start` when it differs from one. The list-item handler at 215,357 distinguishes loose and tight structures and preserves nested blocks.

The GFM task recognition expression around 9,100 accepts **one arbitrary status character** inside brackets when followed by a space or tab. A space means unchecked; every other recognized character means checked. The original status is retained separately. The transformer at 757,100–757,628 creates task-list/item/checkbox metadata, retaining `data-task` and checked state. This supports styled statuses such as `[-]`, not just `x`/`X`.

Section generation attaches relative line numbers. Checkbox event handling near 2,003,800 resolves that number through its containing section before calling the owner. `toggleCheckbox` at 2,036,399 changes the first bracketed single-character marker on that source line: space becomes `x`; any other character becomes space. The handler patches rendered state and calls the owning edit/save path. It does not round-trip checkbox HTML into Markdown.

The local line loop flattens indented and mixed list types into the type selected by the first item, ignores ordered starts, separates continuation text from its item and accepts only `[ ]`, `[x]`, `[X]`. Its task recognition also allows no following whitespace. These are concrete mismatches independent of styling. Nested list collapse, persisted fold state and indentation guides have additional contracts in [list/fold reference](list-fold-reference.md).

## HTML sanitization

The inspected reference permits Markdown HTML through its AST serializer, then sanitizes before DOM insertion. At 848,000–849,250, the exported `sanitizeHTMLToDom` helper uses the bundled DOMPurify instance and imports the resulting fragment into the current document. Configuration allows unknown protocols, forbids `style` **elements**, adds `iframe`, permits selected iframe/tooltip attributes, and forbids `data-background-iframe`. This does not establish that arbitrary event handlers, scripts or JavaScript URLs survive: DOMPurify has its own tag, attribute and URI checks. Nor does forbidding style elements imply all inline style attributes are prohibited.

A sanitizer hook forces anchors to a new-window target and supplies `noopener nofollow` when rel is absent. Desktop media/file-link adjustment is separately registered near 3,921,721. The full sanitizer implementation, browser parsing edge cases, all allowed SVG/MathML structures, iframe navigation policy and external-protocol policy were not exhaustively audited. No security equivalence claim follows from these configuration observations.

Zorid currently constructs DOM with text nodes and renders supplied HTML literally. That establishes a useful safety property for its current implementation, but differs from safe HTML rendering. An original implementation should retain a maintained sanitizer boundary if adding HTML; copying the inspected option object alone is not sufficient validation.

## Math, Mermaid, callouts and footnotes

**Math.** Inline tokenizer at 757,628 distinguishes single-dollar and double-dollar forms, handles escaped dollars and applies whitespace/digit restrictions around single-dollar delimiters. Block tokenizer at 758,450 handles multi-dollar fences and participates in paragraph/list/quote interruption. Nodes carry separate inline/block math classes. At 2,027,125, a postprocessor waits for MathJax, converts to CHTML, falls back to source text on conversion failure, marks completion and schedules stylesheet refresh. A recycler matches original source and display mode.

MathJax setup at 1,994,800–1,996,400 disables automatic delimiter/environment/reference processing and automatic startup typesetting, configures extension packages and calls `tex2chtml` explicitly. Safe-protocol options deny JavaScript/data and permit HTTP/HTTPS/file in that library configuration; this is not a whole-app URL policy. The library identity is `lib/mathjax/obsidian-mathjax.js`, SHA-256 `ac00d774192009417b8fa50412f4b27f94426014e7526fe1151276a9784de965`. Its full implementation and supported TeX corpus remain uninspected here.

**Mermaid.** Deferred setup at 1,993,980 initializes manual rendering with strict security level and per-diagram sizing options. Renderer at 2,023,173–2,025,200 uses measured available width, a temporary hidden container and a unique ID, handles errors, adjusts marker IDs and internal-link labels, and defers rendering when not shown. A recycler matches the diagram source. Crucially, desktop registration at 3,921,721 consults a **vault-local trust setting**. Helpers at 2,696,370–2,697,500 show guarded source and an Allow action until that state is enabled; changing it triggers postprocessor refresh. Published-page registration at 2,438,801 differs, so its unconditional renderer must not be mistaken for desktop policy. Library SHA-256: `6ef73c979e4636b0724eb3b4ee505e53e3a117e4cae31914ec5b2d64f27ff603` for `lib/mermaid.min.js`. Diagram internals and runtime results are unresolved.

**Callouts.** Quote tokenizer at 177,300–178,350 recognizes a first-line callout marker, optional `+`/`-`, and optional pipe metadata. It normalizes type to lowercase with whitespace changed to hyphens, then recursively parses content. Transformer/handlers at 767,384–769,100 split title and body while preserving inline/block children and synthesize a title from type when absent. DOM carries type, fold and metadata; the handler can carry icon/color fields, but the source of every possible field was not traced. Postprocessing around 2,029,000–2,031,000 adds icons and fold interactions. `-` initially collapses; `+` initially expands; links in the title retain their event route before the deferred title-click fold action. Zorid currently uses a plain-text title, treats fold markers as title text and parses following quote lines only inline.

**Footnotes.** Tokenizers at 759,713–762,400 support `^[inline content]`, `[^label]` and block definitions with continuation content. Inline notes account for nested brackets, escapes and code delimiters. Definition/reference identifiers are lowercased. Transformer at 764,000–766,300 numbers by reference encounter, groups repeated references with distinct reference identifiers, appends backlinks, and creates a final footnotes section. Undefined reference handling in this inspected transform emits identifier text; broader malformed cases remain unverified. Postprocessor at 2,022,800–2,023,200 suffixes identifiers and hrefs with the document ID, avoiding collisions between rendered documents. Click handling near 2,003,400 locates the target section, reveals it and scrolls/highlights; hover uses the note reference identity.

**Comments.** At 769,700–770,900, separate inline and block `%%` tokenizers produce comment nodes; the HTML handler omits them. Block comments participate in paragraph/list/quote interruption, and an unterminated block comment consumes remaining input in that branch. A raw global removal regex would risk deleting comment-like text inside code or escapes. The current renderer displays these markers and contents.

**Reference links/images.** Baseline grammar includes full, collapsed and shortcut references (178,350 onward). Definitions are indexed case-insensitively with the first entry retained (198,300–198,800), and HTML handlers at 199,982 and 39,301 resolve destination/title or use a fallback for missing definitions. Document-wide indexing before section rendering means a definition later in another section can still resolve. Custom footnotes explicitly avoid being consumed as normal link definitions. Direct-link conversion to internal links does not by itself prove identical conversion for `linkReference` nodes; reference-link routing deserves a dedicated fixture. Zorid's current renderer has no definition/reference stage.

## Postprocessors and component lifecycle

At 2,019,681, the registry sorts callbacks numerically by sort order, defaulting to zero. Code-block registration at 2,020,020 rejects a duplicate language. Its wrapper finds language-classed code, replaces the enclosing preformatted block with a language container, calls the supplied processor, and collects any returned promise. A source-aware replacement callback uses section and relative code-line information and checks the captured code text before replacing it.

Plugin registration near 2,948,300–2,949,000 triggers `post-processor-change` on registration and unregisters callbacks/languages on unload, triggering refresh again. Context carries document ID, source path, frontmatter, component registration, section lookup, replacement, container and display information. Public `render` warns when a plugin omits a Component because children may register global listeners. This is a lifecycle and source-mapping API, not just a callback array.

Built-in processors include frontmatter hiding, footnote ID isolation, copy-code buttons, Prism highlighting (sort order 100), math, callout controls, table overflow/direction and text direction. Image handling assigns no-referrer policy and waits for load/error. Recyclers reuse compatible code, math, embeds, images and Mermaid output. Their presence and branch behavior were traced; exact scheduling, performance, failure ordering and all plugin interactions remain unverified. `lib/prism.min.js` identity is SHA-256 `9389ca2110991b037228c190018c94abcf25d1af0ad32fc51b78263660acbddb`; its language implementations were not audited.

## Original inline implementation follow-up

`src/ui/markdown-inline.ts` adds `renderMarkdownInline(parent, source, open, options)` with type-only imports of the existing Markdown callback interfaces. It appends using the parent's owner document. The block renderer can delegate its `inline` function to this export without a runtime import cycle. This module does not itself replace the block renderer or claim complete reference conformance.

The implementation uses the already installed CodeMirror Markdown language's Lezer grammar, with block parsing disabled and original inline extensions for wikilinks, paired single-line comments and two-equals highlights. Lezer supplies nested asterisk/underscore emphasis, strong emphasis, strikethrough, variable-length code delimiters, escapes, entities, link labels/destinations and autolinks. Image alternate text is derived without invoking nested embed callbacks. Wikilink aliases remain plain text; target normalization includes NFC and nonbreaking spaces. Each recognized image invokes the existing embed callback once. HTTP/HTTPS and mail links receive safe external anchor attributes; local links retain the application's callback route. JavaScript, VBScript and data destinations become inert labels rather than navigation or embed requests.

All ordinary note output is created with DOM/text APIs. Raw HTML nodes remain literal text. A narrowly validated HTML entity token can be decoded in a detached textarea; only its text value is subsequently inserted. No source HTML fragment is appended or interpreted as executable note markup. This remains a safe subset rather than the reference's sanitized HTML feature.

Known gaps are explicit: definition/reference resolution, footnotes, math, tags, block IDs, highlight color prefixes and longer equals runs have no special rendering here. Unresolved references, HTML, math and other unsupported nodes remain literal. Multiline/block and unterminated comments remain literal; the block renderer must own those cases. Image-size suffix interpretation stays with the existing embed callback. The Lezer grammar is not asserted to reproduce every branch of the inspected parser, including exotic delimiter, reference and malformed-link cases. Async postprocessors, component ownership, source-section replacement and safe HTML support remain separate work.

Focused `tests/markdown-inline.test.ts` covers nested formatting, delimiter/escape precedence, Unicode and normalized wikilinks, source destination decoding, image callback counts, code whitespace, comments, unsupported syntax, owner-document handling and inert HTML/unsafe protocols. These are original implementation tests; they do not execute the reference or certify visual/browser navigation parity.
