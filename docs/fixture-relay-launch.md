# Disposable cross-client relay fixture

Source-stage integration tooling; actual browser/Electron/CLI convergence is not
established by this launcher. It provisions only fresh synthetic accounts and
vaults through the existing RelayStore library and serves its real loopback router.

```sh
cargo run --offline -p zorid-sync-server --example fixture-relay -- /private/tmp/zorid-crossclient-UNIQUE 0 http://127.0.0.1:8767
```

The directory must be absolute, nonexistent and outside all client vault roots.
Its parent must exist. The launcher creates it with mode 0700 and credential
files with mode 0600. Port 0 chooses an available loopback port. Use the exact
browser application origin (including port, no trailing slash) for CORS.
The command prints only the manifest path. Ctrl-C stops the server; fixture files
are retained, including partial startup artifacts. It never replaces or removes
an existing directory. This is Unix-only tooling, matching current CLI fixture
credential permission support.

`manifest.json` contains endpoint, realm, epoch, account/device/vault identifiers
and credential filenames, but no vault keys or bearer tokens. Account A owns
vault A with independent web, CLI and desktop credentials; account B owns vault B
with CLI credentials for isolation checks. Each vault has a fresh independent
random key. These disposable client keys are generated by test setup, not by the
production relay architecture.

Each credential file exactly matches the CLI format:
`version`, `endpoint`, `realm_id`, `vault_id`, `server_epoch`, `key_epoch`,
`key_base64`, `bearer_token`. Pass its absolute filename through the CLI's
`sync --credentials` option. Do not print or serve these files over HTTP.

The browser fixture imports one selected local credential file explicitly and
maps fields to its worker configuration:

- endpoint -> endpoint
- realm_id / vault_id / server_epoch / key_epoch -> realmId / vaultId / serverEpoch / keyEpoch
- bearer_token -> bearerToken
- key_base64 -> decoded 32-byte keyBytes
- explicit fixture options: allowLoopbackHttp:true, enrollEmpty:true

Worker credentials stay in memory; reimport after restart. The launcher does not
seed browser IndexedDB or native client state. Create content through actual core
commands and transfer genesis through sync. No test-only bypass proves convergence.

For restarting the SAME relay, read its port/realm from the manifest and use the
existing binary (use the original numeric port so credential endpoints stay valid):

```sh
cargo run --offline -p zorid-sync-server -- /private/tmp/zorid-crossclient-UNIQUE/relay.sqlite fixture-realm ORIGINAL_PORT http://127.0.0.1:8767
```

A restart reuses the existing server epoch and account/device authorization. An
encrypted backup restore has a separate epoch/reauthorization flow and must not
be simulated by editing credential files to suppress mismatch detection.
