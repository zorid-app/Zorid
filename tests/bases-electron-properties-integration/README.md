# Supplemental ordinary property campaign

This is an **authored, source-only campaign**, pending actual execution. It runs
through the shared frozen Electron runner's optional campaign-module interface.
It does not build, pick artifacts, launch on import, or mutate production APIs.
The runtime owner must reserve the normal bounded desktop pass, supply exact
frozen artifacts/HEAD and retain the runner's evidence and process cleanup.

```sh
node tests/bases-electron-integration/run.mjs \
  --root /absolute/frozen/worktree \
  --expected-head FULL_FROZEN_COMMIT \
  --native /absolute/frozen/zorid-host \
  --electron /absolute/Electron.app/Contents/MacOS/Electron \
  --out /private/tmp/NEW-properties-evidence-directory \
  --ready bases-native-and-frontend-frozen \
  --campaign-module /absolute/worktree/tests/bases-electron-properties-integration/campaign.mjs
```

The campaign module must be among the runner's explicit allowed filenames; the
coordinator owns that shared runner. This fixture owns its entire six-file vault,
including ordinary `Properties.yaml`. Prelaunch fixture creation is not user
creation coverage. Two source notes, two target notes and one Base cover all
configured value types without repeating the heavy user's view settings or CAS
and failure campaigns.

Each alternative layout has actual editing actions. The Kanban status edit must
publish exactly one Alpha card inside the actual `Complete` column before the
next edit. All property selectors are scoped to the active pane.

`raw-oracle.mjs` contains fourteen preauthored source edits plus two registry
option insertions. These edit fixed expected spans seeded from `fixtures.mjs`;
they never copy a read/save result or call the product serializer. The Alpha
fixture includes preserved double/single quotes, a frontmatter comment, an
edited scalar comment, an unrelated scalar comment and exact body text. Every
saved property operation checks full raw bytes as well as the independent typed
property model. The Base, Beta and both target notes must remain byte-for-byte
identical to their prelaunch source. All six files, including the independently
patched registry, are asserted before quit, offline, and after fresh launch.

Each alternative layout has actual editing actions. P6's Cards/List/Kanban portion
is explicitly **inspection**, since their value/card activation may correctly
navigate rather than edit. It is not described as keyboard edit rejection in
those layouts. Existing positive persistence/body checks also assert that derived
properties are never added to the note source.

The normal controls are located/read by DOM inspection, then operated through
actual CDP pointer and keyboard input. Relation chips navigate, so picker entry
uses neutral widget padding or real Tab navigation and Enter. No scripted focus,
`element.click`, dispatched edit event, private workspace call, injected resolver
or test-only candidate source is used. An unavailable control fails with retained
failure DOM; it is never silently skipped. The plain `link` type intentionally
asserts the ordinary picker path and will expose missing core-advised candidates.

No external editor, hostile input or failure fixture is part of this campaign.
Those belong to the separately labeled safety campaign. Screenshots document this
fixture's actual views and interaction state; they do not establish matched
viewport/reference pixel parity, mobile, OS keyboard or arbitrary crash coverage.
