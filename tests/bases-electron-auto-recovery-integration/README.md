# Automatic accepted-Base recovery — authored Native campaign

This new campaign is separate from the terminal permission-denial Review/Copy
campaign. It uses the existing public Native collection scene: real returned
schema IDs, two independently authored member notes (scores 2/3), exact complete
Base sources, stable first-view ID and untouched sibling definitions.

No actual Native/app run has been performed by this worker. The common runner
must freeze and authenticate the current packaged artifacts and every imported
campaign helper before acceptance:

```sh
node tests/bases-electron-auto-recovery-integration/run.mjs \
  --root /absolute/frozen/worktree \
  --expected-head FULL_40_CHARACTER_COMMIT \
  --electron /absolute/frozen/Electron.app/Contents/MacOS/Electron \
  --native /absolute/frozen/zorid-desktop-host \
  --out /absolute/new/owned-output \
  --show-window \
  --ready bases-native-and-frontend-frozen
```

Each phase opens its own supported file, `AutoBusy.base` or `AutoHost.base`.
Trusted input submits A (`values.length`), holds only its genuine successful
inert preparation, and types newer B (`values.sum() + 7`) through the exact
already-focused editor. Before the fault, the same panel/editor identity and
complete raw B are required; neither source has committed.

- **SQLite writer contention:** a separately owned Node helper opens only the
  existing authenticated `.zorid/vault.sqlite` via no-create URI mode. It checks
  canonical directories, file/sidecar identities, ownership, SQLite header,
  ZORD application ID, schema 20 and WAL mode. Its only transaction statements
  are `BEGIN IMMEDIATE` and `ROLLBACK`. After the real busy checkpoint response
  is observed and matched to the original request, rollback and normal helper
  exit release the lock. The app must retry the exact original CAS and commit
  original A automatically. The live database is never edited by the helper.
- **Native process loss:** the common runner freshly authenticates the current
  generation and sends SIGKILL only to that genuine Native child. The relay
  discards the withheld ACK and exposes actual child EOF. Main must bind a new
  live generation automatically. Positive wire admission must prove the same
  client/store hashes and a fresh lease hash before the original A operation
  completes. Actual dispatched capture/prepare/checkpoint/commit lease-header
  hashes must match that positive claim; matching client names alone is insufficient. No response, admission, error or wake is synthesized.

During either recovery interval the campaign sends no Save command, blur,
reload, navigation, cancel or product recovery call. It does not manually wake
retry timers or claim a client. Reads are standard passive DOM/frame evidence,
physical byte checks and ordinary bridge read/stat verification. A passive
mutation-plus-animation-frame observer rejects error flashes and generic manual
recovery controls; every terminal path disposes observers and owned locks.

The original source capture ID hash, returned witness, S0 body digest, prepare
command/mutation/body, operation ID, inert intent token hash and checkpoint
expected/next revisions must remain exact. This demonstrates wire continuity;
it does not inspect Native private source-guard internals. A closed request
inventory rejects unknown/direct source authoring and any B body dispatch.
Same app PID, CDP document, entry, file source and selected stable view must
survive. Busy keeps the original pane/tab/editor DOM. Host recovery may rebuild
the presentation: the original DOM tab UUID first chooses one existing
window-scoped persisted session. The same key's Core-scope digests must match
the real admission. Stable pane ID, fixed tab position, complete non-ID
descriptors, active pane and layout remain exact, using only the explicit
Workspace restore defaults. The initial mapping from saved panes to actual DOM
positions is preserved even when saved-array order differs from split-layout
order. Fake UUIDs, ambiguous peers, moved slots, changed descriptors and wrong
complete active/selected mappings fail permanently. No path search, storage
setter or private Workspace API is used. Only key/descriptor/layout/scope hashes
and bounded occurrence metadata are exported. Replacement DOM IDs are recorded,
and raw B plus its selection/focus must restore to that exact logical target. All independent whole-file and sibling source oracles remain.

Acceptance is sealed only after A has one genuine successful commit ACK, the
exact physical/bridge A source is verified, B remains raw for an independent
350 ms interval, and no B preparation/commit exists. A separate, explicitly
labeled trusted Tab then submits B as a new ordinary user operation, verifies
its full bytes and receipt, and permits normal app/healthy-Native quit. That
post-seal B authoring is not part of automatic recovery. The intentionally
killed Native generation is the only expected abnormal exit; no app or other
Native generation may leak. Raw B is RAM custody, not claimed crash-durable.

Pure contracts and actual temporary SQLite contention checks use bounded Node
concurrency and execute no Native binary or app:

```sh
node --test --test-concurrency=1 \
  tests/bases-electron-auto-recovery-integration/sqlite-writer-fault.test.mjs \
  tests/bases-electron-auto-recovery-integration/oracles.test.mjs \
  tests/bases-electron-auto-recovery-integration/quiet-observer.test.mjs \
  tests/bases-electron-auto-recovery-integration/session-occurrence.test.mjs
```

Illustrative metadata in the oracle tests never establishes a real fault or
fresh admission. Packaged automatic-recovery acceptance remains the integration
owner's actual run with the reviewed relay and generation registry APIs.
